# Анхны сэтгэгдлийн аудит (first-impression audit)

Сценари тестийн ӨМНӨ ажиллуулна. Зорилго нь "хэрэглэгч даалгавраа
гүйцэтгэж чадах уу" гэхээс өмнө **"дэлгэцийг хараад юу гэсэн газар,
юуг засах гэж байгаагаа нээхгүйгээр ойлгох уу"** гэдгийг шалгах.

## 0. Дүр

Чи энэ системийг **анх удаа** нээж буй хүн. Өмнөх тестийн мэдлэг,
кодын мэдлэг, "энэ нь ийм байх" гэсэн таамаг ХЭРЭГЛЭХГҮЙ. Зөвхөн
дэлгэцэн дээр бичигдсэн, зурагдсан зүйлээр дүгнэнэ. Хэрэв ямар нэг
зүйлийг ойлгохын тулд (а) дарж нээх, (б) хулгана дээр нь барих,
(в) кодыг унших шаардлагатай бол — энэ бол олдвор.

## 1. Дэлгэцийн жагсаалт — НЭГ БҮРЧЛЭН

Эхлээд шалгах дэлгэцийн бүрэн жагсаалтыг гарга, дараа нь нэг нэгээр
нь доорх 8 асуултаар дуусга. Нэг дэлгэц зөв байна гэдэг нь бусад нь
зөв гэсэн үг БИШ (CLAUDE.md → "ЦУВРАЛААР нь шалга").

Админ (`http://localhost:8080/admin/`):

| # | Дэлгэц | Хаанаас |
|---|---|---|
| A1 | Виджет ба дата → хэсгийн картууд | анхны дэлгэц |
| A2 | Зүүн багана — мод (Цэсээр / Датасэт / Салбараар / Төлөвөөр) | 4 өнцөг тус бүр |
| A3 | Хэсэг доторх виджетийн жагсаалт | хэсгийн карт дээр дарах |
| A4 | Бүх харагдац | "Бүх харагдац" товч |
| A5 | Виджетийн засварын дэлгэц | виджет дээр дарах |
| A6 | Модаль цонхнууд (◧ ⌖ ↻) | жагсаалтын дүрс товч |
| A7 | Сайтын текст таб | 2-р таб |
| A8 | Дата холболт таб (дата сан, метрик, чарт, каталог) | 3-р таб |
| A9 | Доод мөр (хадгалах / экспорт / нийтлэх) | бүх дэлгэц |

Нийтийн сайт (`http://localhost:8080/`): Нүүр (hero → 08-р хэсэг),
`#/eservices`, `#/browse`, `#/browse/<slug>`, `#/community`,
`#/history`, `#/news`.

## 2. Дэлгэц бүрт тавих 8 асуулт

| # | Асуулт | Олдвор гэж үзэх нөхцөл |
|---|---|---|
| Q1 | **5 секундын тест** — дэлгэцийг 5 сек хараад "энэ юу вэ, энд юу хийх вэ, хаанаас эхлэх вэ" гэдэгт хариулж чадах уу? | Гарчиг/тайлбар алга, эсвэл эхлэх цэг олон ба тэнцүү жинтэй |
| Q2 | **Таних (recognition over recall)** — жагсаалтын мөр бүр сайт дээрх харагдацаараа (жижиг preview, бодит текст, хэлбэр) танигдах уу? | Мөр зөвхөн нэр/ID/замаар танигдах, нээж байж л юу болохыг мэдэх |
| Q3 | **Байршил** — засах гэж буй зүйл сайтын ХААНА гарахыг нүдээр харуулдаг уу (байршлын схем, "Сайт дээр харах ↗")? | Зөвхөн бичвэрээр "03-р хэсэг" гэх мэт тайлбарлах, сайт руу үсрэх холбоосгүй |
| Q4 | **Нэр томьёо** — анхдагч харагдацад raw түлхүүр (`site.brand.mark`), файлын нэр, англи товчлол, код гарч байна уу? | Энгийн хэрэглэгчид утгагүй тэмдэгт мөр гол мэдээлэл мэт харагдах |
| Q5 | **Ачаалал** — нэг дэлгэцэд хэт олон элемент уу? Агуулгын тойм (TOC), хураах, хайх, шүүх бий юу? | ~7-оос олон бүлэг эсвэл ~40-өөс олон талбар тоймгүй, хураалтгүй цувах |
| Q6 | **Дараагийн алхам** — хоосон / анхны / алдааны төлөвт юу хийхийг хэлдэг үү? | Хоосон дэлгэц, "олдсонгүй" гэхээс цааш зам заахгүй |
| Q7 | **Чиг баримжаа** — би хаана байна, яаж буцах вэ (зам мөр, Back, идэвхтэй таб)? | Буцах зам алга, хөтчийн Back сайтаас гаргах |
| Q8 | **Тэмдэг ба өнгө** — ✓ ! ✕, өнгөт цэг, badge бүр үгээр тайлбарлагдсан уу? | Тэмдгийг хулгана барьж байж л ойлгох |

Хариулт бүрийг `read_page` / `get_page_text` / `screenshot`-оор
**бодитоор** ажиглаж бич. Кодоос таамаглаж бүү бич. Богино хугацааны
элемент (toast, hover) алдагдахаас болгоомжил — хэрэв эргэлзэж байвал
кодоор нягтал (qa-backlog дахь "залруулга"-ын жишээг үз).

## 3. Жишиг — ижил төрлийн хэрэгслүүд юу хийдэг вэ

Олдвор бүрд доорх жишгээс хамгийн ойрыг нь нэрлэж, "тэд юу хийдэг"
гэдгийг 1 өгүүлбэрээр бич. Таамгаар биш, жишгээр шийднэ.

| Хэвшил | Жишиг | Хэзээ хэрэглэх |
|---|---|---|
| **Бодит харагдацтай жагсаалт** (thumbnail/mini preview) | Shopify theme editor-ийн section list, Webflow Navigator, Tableau Public / Our World in Data графикийн галерей | Жагсаалтын мөр нь сайт дээр ЗУРАГДДАГ зүйл бол |
| **Одоогийн утгаа харуулсан хураангуй мөр** | Contentful / Strapi / Directus-ийн entry list (гол талбарын утга багана болж гарна) | Текст талбарын урт жагсаалт |
| **Байршлын схем + "сайт дээр харах"** | Sanity Presentation, Storyblok Visual Editor, WordPress Customizer-ийн ✎ товч, Shopify "View on store" | Засварлах зүйл сайтын тодорхой хэсэгт байгаа бол |
| **Хуудсаар бүлэглэсэн тойм (TOC) + хураах** | Shopify theme editor (Header / Template / Footer), Webflow Pages panel, GOV.UK "contents" | Нэг дэлгэцэд олон бүлэг |
| **Хоосон төлөвт дараагийн алхам** | GOV.UK Design System, CKAN / data.gov.uk хайлтын "олдсонгүй" хуудас | Хайлт, шүүлт, анхны төлөв |
| **Төлөвийг өнгө + ҮГЭЭР** | GOV.UK tag, Atlassian lozenge, WCAG 1.4.1 | ✓ ! ✕ мэт тэмдэг |

## 4. Хамгийн оновчтой хувилбарыг сонгох

Олдвор бүрд **2–3 хувилбар** бичиж, дараах 4 шалгуураар (1–3 оноо)
үнэлээд хамгийн өндөр нийлбэртэйг сонго:

1. **Ойлгомж** — анх орсон хүн нээхгүйгээр ойлгох уу
2. **Энэ архитектурт нийцэх** — `content.json` (ганц эх сурвалж),
   `utxt()` / `stxt()`, preview-сайтын паритет, `previewFor()` дахин ашиглах
3. **Эрсдэл** — урвуулж болох, fallback-тай, одоо байгаа тест эвдэхгүй
4. **Өртөг** — хэрэгжүүлэх хэмжээ

Жишээ (A3/A7-ийн Q2): "виджетийн нэр л харагдана" →
(а) нэрийн хажууд hover tooltip — ойлгомж 1;
(б) мөр бүрд `previewFor(id,true)` жижиг preview — ойлгомж 3, нийцэл 3;
(в) тусдаа screenshot зураг хадгалах — эрсдэл 1 (хуучирна).
→ (б)-г сонгоно.

## 5. Тайлан

`qa-backlog.md`-д агентын үндсэн загвараар бичнэ, нэмэлтээр:

```
- Ангилал: Анхны сэтгэгдэл (Q<дугаар>)
- Жишиг: <нэр> — <тэд юу хийдэг, 1 өгүүлбэр>
- Хувилбарууд: (а) … [о/н/э/ө = x/x/x/x] · (б) … · (в) …
- Сонгосон: (б) — <яагаад>
```

Эцэст нь дэлгэц × асуултын **хүснэгт** (✓ / ! / ✕) бичиж, аль дэлгэц
хамгийн сул байгааг нэг өгүүлбэрээр дүгнэ.

## 6. Хөгжүүлэлт рүү шилжүүлэх

- `ux-qa-persona` агентаар ажиллаж байгаа бол **кодыг өөрөө засахгүй** —
  олдвор + сонгосон хувилбарыг бичээд зогсоно.
- Үндсэн сешн дээр ажиллаж байгаа бол сонгосон хувилбарыг CLAUDE.md-ийн
  "Тестийн мөчлөг"-өөр хэрэгжүүлнэ: тест ЭХЛЭЭД (`tests/run.js`) →
  шинэ текстийг `content.json`-д бүртгэх → админ ба сайт ХОЁУЛАНГ
  browser-оор шалгах → `check-cyrillic` → `check-registry` →
  `tests/run.js` → `tests/text-coverage.js`.
- Засвар бүрийн дараа тухайн дэлгэцийн 8 асуултыг ДАХИН асууж, олдворыг
  `[ХААГДСАН]` болгохдоо юугаар баталгаажуулснаа бич.
