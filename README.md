ЗТЯ-ны дата портал

## Датасэтийн "Үзсэн" тоолуур

Датасэт бүрийн үзэлтийг `js/dataset-views.js` бүртгэнэ. Хоёр горимтой:

- **Локал (одоо ажиллаж байгаа)** — `localStorage`. Backend шаардахгүй, шууд
  ажиллана. Гэхдээ энэ нь **зөвхөн тухайн хөтчийн** тоо, хэрэглэгч бүр өөрийн
  тоог хардаг.
- **Дундын (Firestore)** — бүх хэрэглэгчийн нийт тоо. Код бэлэн, Firestore
  идэвхжмэгц **өөрчлөлт хийхгүйгээр** автоматаар шилжинэ.

### Дундын тоолуурыг идэвхжүүлэх

1. [Firebase Console](https://console.firebase.google.com) → `open-data-62ed3`
   → **Build → Firestore Database → Create database** (production mode).
2. **Rules** таб дээр дараах дүрмийг тавина:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /datasetViews/{id} {
      allow read: if true;
      // Зөвхөн count талбарыг 1-ээр нэмэхийг зөвшөөрнө.
      allow create: if request.resource.data.count == 1;
      allow update: if request.resource.data.count == resource.data.count + 1;
    }
  }
}
```

3. Хэдэн минутын дараа сайт автоматаар дундын тоог уншиж эхэлнэ.

**Анхаар:** дээрх дүрэм нэвтрээгүй хэрэглэгчид бичихийг зөвшөөрдөг тул тоог
зохиомлоор өсгөх боломж нээлттэй. Үүнийг хаах бол
[App Check](https://firebase.google.com/docs/app-check) нэмэх, эсвэл
нэвтэрсэн хэрэглэгчээр хязгаарлана (`allow write: if request.auth != null`).

## Хэрэглэгчийн дата (Firestore)

Профайл, үнэлгээ, сэтгэгдэл, дагалтыг `js/erthub-store.js` хариуцна.
`dataset-views.js`-тэй адил **Firestore SDK татахгүй**, зөвхөн REST ашиглана —
Auth SDK аль хэдийн ачаалагдсан тул ID token-оо түүнээс авч
`Authorization: Bearer` толгойд явуулдаг. Ингэснээр Security Rules доторх
`request.auth` бүрэн ажиллана, харин багц хэмжээ ~300KB-аар өсөхгүй.

### Коллекцууд

| Зам | Агуулга | Хэн уншиж чадах |
|---|---|---|
| `users/{uid}` | Профайл — эрх, регистр, утас, байгууллага | Зөвхөн эзэн нь |
| `items/{itemId}` | Нэгтгэсэн тоо — дагагч, үнэлгээ, сэтгэгдлийн тоо | Бүгд |
| `items/{itemId}/ratings/{uid}` | Нэг хүний нэг үнэлгээ (1–5) | Бүгд |
| `items/{itemId}/reviews/{autoId}` | Сэтгэгдэл | Бүгд |
| `items/{itemId}/follows/{uid}` | Дагалт | Бүгд |
| `datasetViews/{slug}` | Датасэтийн үзэлт | Бүгд |

**Гол загвар:** үнэлгээ болон дагалтын баримтын ID нь `uid` өөрөө. Ингэснээр
нэг хүн хоёр удаа үнэлэх/дагах боломжгүй болно — хоёр дахь бичилт хуучнаа
дарна. "Энэ хэрэглэгч үнэлсэн үү?" гэж тусад нь хайх шаардлагагүй.

`itemId` нь `dataset__<slug>`, `doc__<slug>` хэлбэртэй. Slug нь гарчигнаас
гардаг тул **гарчиг өөрчлөгдвөл тухайн объектын үнэлгээ, сэтгэгдэл тасарна.**
Үүнийг бүрэн шийдэх бол `DATASETS`, `DOCS` бүрд гараар өгсөн тогтмол `id`
талбар нэмэх хэрэгтэй.

### Идэвхжүүлэх

1. [Firebase Console](https://console.firebase.google.com) → `open-data-62ed3`
   → **Build → Firestore Database → Create database** (production mode).
2. **Rules** таб руу репо дэх [`firestore.rules`](firestore.rules)-ыг бүтнээр
   нь хуулж **Publish**.

Хоёр алхмыг хийтэл сайт **demo горимд** ажиллана: Firestore `404 database
does not exist` буцаахад `erthubStore.available` нь `false` болж, UI нь
хуучин статик утгуудаа хэвээр харуулна. Код өөрчлөх шаардлагагүй.

### Хязгаарлалт

- Тоолуурыг клиент талаас `increment` хийдэг тул шийдэмгий халдагч тоог
  гажуудуулж чадна. Бүрэн хамгаалалт нь Cloud Functions шаардах ба тэр нь
  Blaze төлөвлөгөө хэрэгтэй.
- `datasetViews` нь нэвтрээгүй хүнээс ч бичилт хүлээн авдаг (үзэлтийг
  нэвтэрсэн хүнээр хязгаарлах нь утгагүй тул). App Check нэмж чангаруулж
  болно.
- Сэтгэгдлийн `hidden` талбар нь UI-д л нуудаг. Дүрмээр хаах гэвэл
  жагсаалтын хүсэлт бүхэлдээ унах тул уншилт нээлттэй — үнэхээр арилгах бол
  баримтыг устгана.

## Картын утгыг датасэттэй холбох

Дэлгэрэнгүй хуудасны картууд бодит өгөгдлөөс утгаа авдаг. `index.html` доторх
`DATA_BINDINGS`-ийг үз — гурван алхамтай:

1. `applyRealFlightsData()` бодит мөрүүдээс `this._liveStats[салбар]`-ыг бөглөнө.
2. `DATA_BINDINGS[салбар][нэр]` тэр статистикийг `{label, value}` болгоно.
3. Датасэт `live:{картынТалбар:'нэр'}`-ээр аль холболтыг дуудахаа сонгоно.

Зарлаагүй бол `DATASETS` доторх статик текст хэвээр үлдэнэ.
`DATA_BINDING_DEFAULTS` нь бүх датасэтэд автоматаар үйлчилнэ (жиш. `use` →
`views`). Бодит өгөгдлөөс тооцсон утгын хажууд ногоон цэг гарна.

## Тээврийн хэрэгслийн бүртгэлийн самбар (`#/vehreg`)

Улсын бүртгэлийн 15 үзүүлэлтийг (6 KPI · насжилт · 5 бөөрөнхий · 3 TOP 8)
нэг хуудсанд харуулна. Слотын **бүтэц** нь `index.html` доторх
`VEHREG_KPI` / `VEHREG_SHARE` / `VEHREG_TOP` / `VEHREG_AGE`, **текст** нь
бүхэлдээ `content.json → site.vehreg{}` (админаас засварлагдана).

**Одоогийн төлөв — тоо ХАРАГДАХГҮЙ.** Эх сурвалж
(`road.veritech.vehicle_registry`, Veritech indicator `14996840`,
1,942,315 мөр) нь нийт мөрийнхөө **0.05%**-ийг л буцаадаг: `offset` нь
хуудасны дугаар биш мөрийн индекс шиг ажиллаж `pageSize + 1` мөрөөс цааш
өгөхгүй, `criteria` шүүлт үл тоогдоно, `pageSize` дээд хязгаартай.
Хэмжилт ба эх сурвалж руу илгээсэн хүсэлт:
`etransport-backend/docs/veritech-vehicle-registry-request.md`.
"Тоо ЗОХИОХГҮЙ" дүрмийн дагуу слот бүр `—` + шалтгаанаа харуулна.

Хоёр өөр шалтгааныг ХОЛИХГҮЙ:

- **таталт хүлээж буй** (13 слот) — багана нь датасэтэд БАЙГАА
  (`AIMAG`, `BUILDYEAR`, `WHEELNAME`, `FUELNAME`, `OWNERTYPENAME`,
  `PURPOSENAME`, `COUNTRYNAME`, `MARKNAME`, `COLORNAME`, `GENDER`);
  таталт засагдмагц дүүрнэ.
- **нэмэлт эх сурвалж шаардана** (2 слот) — давхардалгүй өмчлөгчийн тоо
  (танигч багана алга) ба эрэн сурвалжлалт (цагдаагийн бүртгэл; энэ
  датасэтийн `STATUS` түүвэрт ганц утгатай). Картан дээр ЯГ юу дутууг
  нэрлэнэ.

### Дөрвөн таб

Эх самбар дөрвөн табтай. Табын **нэр** нь эх дэлгэцээс авсан баримт;
**агуулга** нь зөвхөн `structure` табынх харагдсан тул бусдын слотыг
ЗОХИООГҮЙ. Хаяг нь `#/vehreg/<таб>` — хуваалцахад тэр таб дээр буудаг
(`routeFromHash` → `{page:"vehreg",vehTab}`); танихгүй таб нь `structure`
руу унана, хуудас цагаан болохгүй.

| таб | төлөв |
|---|---|
| `ops` — Үйл ажиллагаа | Слотгүй. Байгууллагын өдөр тутмын үйлчилгээний гүйлгээ хэрэгтэй; бүртгэлийн датасэт нэг мөрөнд нэг ТХ хадгалдаг тул хангахгүй. |
| `structure` — ТХ-ийн бүтэц, өмчлөгч | 15 слот (анхдагч таб). |
| `fuel` — Түлш: цахилгаан, хайбрид | 8 слот. Сэдэв нь `FUELNAME` тул ЭНЭ датасэтээр хангагдана. Слотыг баталгаажсан багананаас (`FUELNAME` · `BUILDYEAR` · `MARKNAME` · `AIMAG` · `CREATEDDATE`) гаргав — эх дэлгэцийн байрлалыг хуулсан БИШ. |
| `plate` — Дугаар хадгалалт | Слотгүй. Дугаар хадгалуулах нь ҮЙЛЧИЛГЭЭНИЙ бүртгэл; `PLATENO` нь одоогийн дугаар, хадгалалтын төлөв биш. |

Слотгүй таб нь хуурамч хоосон карт ӨРӨХГҮЙ — ЯГ ямар эх сурвалж дутууг
нэрлэсэн нэг самбар харуулна (`site.vehreg.need_source`).

### Backend-ийн гэрээ

Самбар нь `GET /api/sectors/road/vehicle-registry`-г уншина
(`js/erthub-backend.js → fetchVehicleRegistry()`). Зам одоогоор
**нээгдээгүй** (404) — `fetchJson` нь `null` буцаадаг тул сайт яг өмнөх
шигээ ажиллана. Хүлээгдэж буй хариу:

```json
{
  "sector": "road", "metric": "vehicle_registry",
  "status": "ok", "as_of": "2026-09-29", "total": 1942315,
  "kpi": { "ub": 0, "rural": 0, "owners": null, "individual": 0, "wanted": null },
  "age": { "avg_years": 13.9, "buckets": [{ "label": "0-3 жил", "count": 0 }] },
  "breakdowns": {
    "wheel": [{ "label": "Баруун", "count": 0 }],
    "fuel": [], "owner_type": [], "gender": [], "purpose": []
  },
  "top": { "country": [], "mark": [], "color": [] },
  "fuel": {
    "ev": 0, "hybrid": 0, "share_pct": 0, "new_12m": 0,
    "mix": [{ "label": "Цахилгаан", "count": 0 }],
    "top": { "mark": [], "aimag": [] },
    "by_year": [{ "label": "2024", "count": 0 }]
  }
}
```

`status` нь `ok` биш, эсвэл хариу ирээгүй бол
`vehicleRegistryToValue()` `null` буцааж самбар хоосон хэвээр үлдэнэ.
Утга `null` ирвэл `—` гэж гарна — `0` нь "тэг ширхэг" гэсэн БОДИТ хариу
тул хоёрыг холихгүй. Хариунд байхгүй бүлэг (жиш. `gender`) нь тэр слотыг
хоосон үлдээнэ, бусдыг нь хөндөхгүй.

Шалгалт: `node tests/run.js --only=VR` (58 тест — арифметик нь гараар
бодогдохуйц фикстур дээр, хоосон ба амьд хоёр төлөв ХОЁУЛАА).

## Админаас сайтад ШУУД нийтлэх

Админ самбар (`admin/index.html`) файл руу бичдэггүй тул засвар нь урьд нь
`Экспортлох` → гар хуулалт → `commit` → `push` хийж байж сайтад гардаг байв.
Одоо **"Сайтад нийтлэх"** товч нь `content.json` / `metric_registry.json`-ий
**дээр давхарлагдах** хувилбарыг **etransport-backend (Postgres)**-д бичнэ;
сайт ачаалахдаа түүнийг уншиж хэрэглэнэ. Дарангуут бүх зочин шинэ текстийг харна.

- API: `GET /api/site-content` (нээлттэй) · `GET /api/site-content/me` ·
  `PUT /api/site-content` (Firebase ID token + `portal_admins`).
- Хадгалалт: `public.site_content_versions` — нийтлэл **бүр шинэ мөр**
  (түүхтэй, буцаах боломжтой). `json` төрөл тул түлхүүрийн дараалал хадгалагдана.
- Нэвтрэлт нь Firebase Auth (Google) хэвээр; backend токеныг Google-ийн нийтийн
  гэрчилгээгээр шалгана. **Firestore сан шаардлагагүй.**
- Давхар нийтлэлээс хамгаална: админ ачаалсан хувилбарын дугаарыг илгээж,
  хооронд нь өөр хүн нийтэлсэн бол backend `409` буцаана.
- Backend унтарсан/сүлжээгүй бол сайт **файлаараа** хэвийн ажиллана — нийтлэл
  бол нэмэлт давхарга, шаардлага биш.

### Идэвхжүүлэх (нэг удаа, серверт)

Дэлгэрэнгүй: etransport-backend репо → `docs/site-content-publish.md`.

1. `git pull` → `npm run migrate` (`009_site_content.sql`).
2. `.env`-д `FIREBASE_PROJECT_ID=open-data-62ed3` нэмээд
   `sudo systemctl restart etransport-backend`.
3. Админ самбарт **Нэвтрэх (Google)** дарахад и-мэйлийн хажууд **uid** гарна.
   Серверт: `INSERT INTO public.portal_admins (email, note) VALUES ('…', '…');`
   (эсвэл `uid`-аар). Хуудсаа сэргээхэд **Сайтад нийтлэх** идэвхжинэ.
4. Firebase Console → **Authentication → Settings → Authorized domains**-д
   `otgonerdene02-cmyk.github.io` байгаа эсэхийг шалгана.

**Шалгах:** `https://portal.mrt.gov.mn/api/site-content`

| Хариу | Утга |
|---|---|
| `{"error":{"message":"Олдсонгүй",…,"path":…}}` | Шинэ код deploy хийгдээгүй |
| `{"error":{"message":"Нийтлэл алга"…}}` | Бэлэн — одоогоор нийтлэл алга |
| JSON (`version`, `content`) | Нийтлэл байгаа, сайт үүнийг давхарлана |

**Буцаах:** серверт өмнөх мөрийг шинэ мөр болгож хуулна —
`INSERT INTO public.site_content_versions (content, registry, published_by_uid, published_by_email)
SELECT content, registry, 'rollback', 'rollback' FROM public.site_content_versions WHERE id = <N>;`

### Нийтэлсний дараа

Нийтлэл нь шуурхай харагдац, git нь бүртгэл. Өөрчлөлтийг **байнгын** болгож
хянахын тулд `Экспортлох` дарж татсан JSON-оо репод хуулж commit хийнэ —
эс тэгвэл файл ба нийтлэл хоёр цаг хугацаанд зөрөх болно.
